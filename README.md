# weealert

> **AI disclosure:** this app was written with AI-assisted coding (Claude by Anthropic). I direct the design, review the code and test it on my own device.

A tiny Android app that makes a different notification sound for each contact, from one source sound, so you can tell who it is without looking at the screen. Pure Java, no libraries, no permissions, tiny APK.

## How it works

In the default *tone patterns* mode, pick a source sound (any audio file Android can play, or one of the built-in sounds) and how many sounds you need. weealert builds that many 1-4 note patterns out of the source: the rhythm and the pitch of each note change from sound to sound. Patterns are picked to be as far apart as possible, because rhythm and melody contour are much easier to learn by ear than tiny pitch shifts.

- The sounds are deterministic. Asking for more later keeps the earlier ones exactly as they were.
- Each sound is named with a random-looking adjective-noun name (`keen-acorn.wav`) that comes from the pattern itself, so a sound keeps its name even when you change other settings.
- Tap a sound in the list to hear it at notification volume. Tap the source name to hear the source note.
- **Export all** writes the WAV files into the folder you choose. Then set each file as a contact's notification tone inside WhatsApp, Telegram, Signal, Contacts and so on. Choosing the `Notifications` folder helps system tone pickers find the files.

Keep it to roughly 5-12 contacts you really need to tell apart by ear. The list shows the closest pair of sounds as a number; higher is easier to tell apart.

## Getting the sounds into other apps

Four ways, use whichever the other app likes:

- **Tone picker:** weealert answers the system tone picker request, so when an app opens its notification tone chooser, weealert is listed in the "Choose an action" list next to the system picker (the same way Zedge shows up). Tap a sound to hear it, press Use, and it is added to the system tones and handed back to the app. Android 10+.
- **File picker:** weealert registers itself as a storage root, so it shows up in the system file picker (look for "weealert" in the sidebar). The sounds are generated when you open them, nothing is stored. Works in any app that lets you choose an audio file.
- **Add to system tones** (Android 10+): adds the sounds to the Notifications tone library, which is what the system tone pickers list. If you change settings and add again, sounds with the same name are overwritten.
- **Export all:** writes WAV files into a folder you choose.

## Built-in sources

All are generated by maths in code, so they cost nothing in APK size: bell, glass, marimba, kalimba, soft sine, beep, water drop and wood tock. (Earlier builds also had a plucked-string and an electric-piano source; both are retired. A saved choice of one of them falls back to the bell, and the ids of the others are unchanged.)

## Contact modes

The Mode button switches between four modes. The first is the original tone-pattern generator and stays the default; the other three work from a contact list and differ in how a name becomes a sound. Switching modes loses nothing.

- **Contacts:** add from the system contact picker (the app receives only the contact you pick and has no contacts permission) or type a name. Names and sounds are stored only on the phone. The name is also used as the tone name, so it shows up in system tone lists; use a nickname if you prefer. Tap a contact to hear it; long-press for *Say it as...*, *New sound* and *Remove*. Each contact gets a sound as different as possible from everyone else's, assigned when it is added, so existing contacts never change when others are added. The list shows how far apart the two closest sounds are; higher is easier to tell apart.
- **Say it as:** the letter-to-sound rules suit names spelled the way they sound, and turn a name into syllables. Names in other scripts get a stable made-up mumble. Spelling a name the way it sounds (for example `jorj` for George) fixes odd cases in all three modes.

### Contact voices

Each name is spoken as a fast mumble in the style of Animal Crossing. A small formant synthesizer (a buzzy pulse train through three moving resonant filters, plus filtered noise for consonants): no recordings, no text-to-speech engine, no network, and the same name always gives the same sound on every phone. Each contact gets its own voice: pitch, vocal tract size, speed and pitch contour. Because it is built like speech synthesis, it sounds like a voice.

### Contact blips

No speech model at all: each syllable of the name becomes one short blip of the source sound chosen above (a file or a built-in, the same one the tone-pattern and name-pattern modes use), so it reads as a synthesised sound. The vowel sets the pitch (bright vowels like "ee" high, dark ones like "oo" low), the first consonant sets how the blip starts (a click for p t k, a hiss for s sh f, a soft start for m n, a glide for l r w y) and the syllable structure sets the rhythm. A contact's voice character is its pitch, speed, blip length and pitch contour, spread as far apart as possible.

### Contact name patterns

The tone patterns of the first mode, played with the source sound chosen there, but each contact's pattern follows the shape of its name: one note per syllable, the pitch from the vowel and the gap from the syllable's weight, snapped to the allowed pitches and gaps. If two names would give nearly the same pattern, the later contact moves to the nearest pattern that is at least *Name pattern separation* away from the others.

Everything else works the same in all modes: tone picker, file picker, Add to system tones, Export, and the max length, level, sample rate and file name settings.

## Tuning one sound

Long-press any sound in the list and choose *Tune this sound...* to change the values of just that sound: the notes and gaps of a pattern, the voice or blip settings of a contact, and the shape and level (note length, fade-out, quieter per note, reverse, peak level and so on). Only values you change are stored; the rest keep following the general settings. A tuned sound keeps its name, so it stays assigned wherever you already set it, and the list marks it *(tuned)*. *Reset tuning* in the same menu undoes it. *New sound* on a contact picks a new assignment and drops the tuned values that belonged to the old one.

## Ringtones

When an app asks for a ringtone (or an alarm tone) instead of a notification tone, weealert answers that too, with the same picker: tap a sound to hear it, press Use. A ringtone is built from the sound like this:

`[prefix sound] gap [the sound, repeated] gap [suffix sound] silence at the end`

with an optional filter (low-pass, high-pass, band-pass or notch) over all of it. The prefix and suffix can be a built-in sound or any audio file you choose, with their own length, volume and gaps. Android repeats a ringtone file by itself with no pause between repeats, so the *gap at the end* is part of the file; the preview loops the file exactly as the phone will, and the picker has a field to change the gap on the spot. Ringtones are saved as `name-ringtone` (alarms as `name-alarm`) in the system Ringtones (Alarms) library, so they sit next to the notification version without replacing it. In the main screen, *Preview as ringtone* makes tapping a sound loop its ringtone version, and *Export as ringtones* writes `name-ringtone.wav` files to the export folder as a fallback.

## Settings

Everything is under *Settings* in the app. The defaults reproduce the original sounds exactly.

**There are no range limits.** Whatever you type is used as typed: any length, any gap in any number of milliseconds (not only multiples of 50), any number of notes, gaps and pitches, decimal pitches such as `-3.5` or `2.25` semitones, any level in dB (above 0 dBFS clips). The only things that are corrected are values that cannot work at all, such as a negative length or an empty list. The only guards are about memory: if the settings allow absurdly many pattern combinations, an evenly spread subset of about a quarter of a million is used, and a ringtone is cut off at about four minutes.

| Setting | Meaning |
| --- | --- |
| Max length | Hard cap for a whole sound. Longer patterns are left out and the renderer trims as a last resort. |
| Note length | How much of the source each note uses. |
| Gaps | The allowed gaps between note onsets, any milliseconds. |
| Fewest / most notes | Notes per sound. |
| Cut notes | End each note when the next one starts, so long sources do not blur together. |
| Pitch offsets | The allowed pitch offsets in semitones, decimals work. |
| Rhythm weight | How much a rhythm difference counts against one semitone when spreading the sounds. |
| Variation seed | 0 is the standard set, any other number gives a different but equally spread one. |
| Fade-out, quieter per note, peak level, sample rate | Shaping and output of the WAV files. |
| Reverse | Play the source backwards. |
| Contact modes | Syllable length, centre pitch, breathiness, longest name, first word only, blip length, name pattern separation. |
| Ringtone | Prefix and suffix sound, their gaps, length and volume, repeats and the gap between them, the gap at the end, minimum ring length, filter type, frequency and resonance, ringtone level. |
| Prefix, numbering | File names: `prefix` + name, or `01-name` in pick order. |

## Build

GitHub Actions only. `test.yml` (manual) builds a signed test APK that installs next to the real app, `release.yml` (manual) bumps the version, tags and publishes a signed APK. Both need the secrets `KEYSTORE_B64`, `KEYSTORE_PASSWORD` and `KEY_ALIAS`.
